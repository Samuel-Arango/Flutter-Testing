# Análisis de requerimientos

Objetivo: comprender qué se debe construir antes de codificar.

## Pasos

1. Identificar actores y casos de uso principales.
2. Listar funcionalidades obligatorias vs opcionales.
3. Definir datos de entrada/salida y reglas de negocio.
4. Identificar restricciones (offline, rendimiento, seguridad, plataformas).
5. Detectar dependencias con servicios externos o BD.
6. Estimar impacto en arquitectura existente.

## Artefactos mínimos

- Lista de casos de uso (actor → acción → resultado).
- Modelo de datos preliminar (entidades y relaciones).
- Criterios de aceptación por funcionalidad.
- Riesgos y supuestos.

## Reglas

- No inventar funcionalidades no solicitadas.
- Validar supuestos con el usuario cuando sean críticos.
- Respetar arquitectura existente salvo justificación técnica.
